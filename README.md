# 抖音 Web 增强

一个计划以单文件 Tampermonkey Userscript 交付的抖音 Web 端增强项目。

## 当前状态

项目目前处于技术设计阶段，尚未提供可安装脚本。当前仓库已经完成：

- 抖音 Web 首页“推荐”标准视频流的真实页面结构调研；
- 视频关键词、弹幕关键词和 BGM 名称过滤的可行性分析；
- 无感过滤、SPA 生命周期、BGM 数据关联和故障降级设计；
- 一轮独立对抗式技术方案审查及修订。

完整方案见：

- [抖音 Web 增强 Userscript 技术方案](./docs/2026-08-13-douyin-userscript-design.md)

在 Stage 0 浏览器证据采集完成前，不应把本仓库描述为已经支持这些功能，也没有可复制到 Tampermonkey 的正式产物。

## 计划功能

### 视频关键词屏蔽

根据推荐视频的标题、描述和话题匹配本地关键词。命中后保持视频画面和音频门控，并进入下一条允许内容。

### 弹幕关键词屏蔽

在弹幕首次绘制前匹配显示文本，只隐藏命中的弹幕，不删除节点，也不改变抖音原生弹幕开关。

### BGM 名称屏蔽

读取页面本来就会接收的视频元数据，根据 `music.title` 或 `musicName` 匹配本地关键词。首版只允许通过 `awemeId/gid` 精确关联视频；无法可靠关联时放行。

## 设计原则

- 单文件 Userscript，同时作为源代码和安装产物；
- 零构建、零第三方运行时依赖；
- 关键词仅保存在 GM 本地存储中，不写入页面 DOM，不发送到网络；
- 不调用抖音私有接口，不发送额外网络请求；
- 不点击“不感兴趣”，不修改账号推荐画像；
- 页面或数据结构不确定时 fail-open，优先保持抖音原生功能可用；
- 站点易变的 DOM 和数据细节集中在内部适配函数中；
- 源码测试、代理真实浏览器验证和用户手工验收分别记录，不互相替代。

## 首版范围

首版只计划支持：

- `https://www.douyin.com/` 首页推荐流；
- `https://www.douyin.com/?recommend=1` 推荐流；
- 标准视频卡片。

首版不承诺支持直播、图文、短剧、放映厅、搜索结果、个人主页、评论区、广告或游戏推广卡片，也不承诺兼容 Firefox、Violentmonkey 和 Safari。

## 无感过滤边界

“无感”的目标是：命中视频不产生可听音频、不进入稳定画面，命中弹幕不先显示再消失，连续命中的预加载视频不逐条闪现。

这些指标仍需在 Stage 0 使用 Edge、Chrome、Tampermonkey、高帧率录屏和音频采样验证。当前方案中的 250ms 视频/BGM 门控和 100ms 弹幕门控只是在可见前台标签页中的目标上限，不是后台标签页或所有浏览器状态下的绝对保证。

如果 `document-start` 注入时序、临时静音恢复或页面响应观察无法满足硬门槛，项目会降低对应承诺，而不是以高风险的 `pause()/play()` 或不可靠数据匹配强行实现。

## 计划开发阶段

1. Stage 0：固化真实 DOM、网络、注入、首帧和音频时序证据。
2. Stage 1：建立单文件脚本元数据、关键词规则、GM 存储和动态菜单。
3. Stage 2：实现视频预判、门控、下一条确认和熔断。
4. Stage 3：实现弹幕首绘过滤和节点复用处理。
5. Stage 4：实现 BGM 元数据安全解析、精确关联和透明响应观察。
6. Stage 5：完成源码检查、浏览器验收和公开交付说明。

## 开发与验证

项目当前没有构建步骤或依赖安装命令。正式脚本创建后，最低验证命令计划为：

```powershell
node --check .\douyin-web-enhancer.user.js
node --test
git diff --check
```

涉及页面选择器、媒体状态、MutationObserver、计时、路由或响应观察时，还必须在最新保存到 Tampermonkey 的脚本副本上完成真实浏览器验证。
