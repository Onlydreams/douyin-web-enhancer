# Stage 0 真实页面证据报告

> 日期：2026-08-13
> 页面：抖音 Web 首页“推荐”流
> 浏览器：Microsoft Edge、Google Chrome + Tampermonkey，均为已登录会话
> 状态：证据采集已收敛；后续 Stage 1 源码已实现。未闭环项已转为后续能力闸门、人工验收或降级承诺，不再阻塞 Stage 0

## 1. 证据边界

本轮使用两类证据：

- Edge 浏览器控制：只读 DOM 结构、真实键盘输入基线和首屏 QuickPlayer 结构；
- Chrome + Tampermonkey：显式启用的 30 秒诊断探针，记录注入、页面原有传输、媒体和弹幕的结构化时序。

诊断探针只在 URL 明确包含 `dwe_stage0_probe=capture` 时运行；普通推荐页完全惰性。`0.2.0` 用于完整结构与时序捕获；仓库当前 `0.2.1` 在此基础上修复 XHR 异步解析和卸载清理，已通过 17 项 Node 回归，并完成一次 Chrome + Tampermonkey 窄范围冒烟实测。

本轮遵守以下边界：

- 未读取 Cookie、Local Storage、浏览历史或账号配置；
- 未点击关注、点赞、收藏、“不感兴趣”或其他推荐反馈控件；
- 未保存作者、评论、弹幕正文、视频 URL、完整请求或响应；
- 未向页面写 DOM，未写媒体属性，未执行页面导航，未发送额外网络请求；
- fixture 只保留字段名、计数、时间和 ID 形状，不保留真实视频 ID 或 BGM 名称；
- 探针结果只能证明本次 Chrome/Tampermonkey 会话中观察到的行为，不能替代正式脚本的实页回归。

匿名摘要位于 `test/fixtures/stage0-chrome-tampermonkey-capture.json`。

## 2. 已确认结果

### 2.1 推荐流、活动卡片和文本边界

稳定状态下，当前推荐流存在唯一活动 `[data-e2e="slideList"][data-active="true"]`，活动标准视频的层级为：

```text
[data-e2e="slideList"][data-active="true"]
  [data-e2e="feed-item"]
    [data-e2e="feed-active-video"][data-e2e-vid]
```

已确认：

- `[data-e2e="feed-active-video"]` 在稳定状态下全文档唯一；
- `data-e2e-vid` 是 19 位十进制字符串；
- 相邻预加载卡片使用 `[data-e2e="feed-video"]`；
- 活动窗口通常保持“上一张 / 当前 / 下一张”三卡，当前卡片位于索引 1；
- Feed 由内部虚拟列表 `transform` 驱动，不是可依赖的标准纵向滚动容器；
- `[data-e2e="video-desc"]` 是描述正文和话题的所有权边界；作者区、章节区和混合信息容器必须排除；
- 话题链接中的 `aweme_id/gid` 抽样可与活动卡片 `data-e2e-vid` 精确关联。

这些选择器适合作为稳定状态下的发现和确认信号，但不能作为“首帧前门控”的唯一早期信号，具体限制见 3.1。

### 2.2 Tampermonkey 注入与页面执行 seam

Chrome 实测捕获确认：

- 探针在 `document.readyState = loading` 时启动，且 `documentElement` 已存在；
- `GM_info` 与 `GM.info` 可用；
- `unsafeWindow` 可用，但脚本 root 与页面 root 不是同一对象；
- 通过 `unsafeWindow` 安装的 `fetch` 和 XHR 包装均观察到了页面原有调用；
- 首次观察到 XHR `open` 约为启动后 226ms，首次观察到 `fetch` 调用约为 2622ms；
- 普通推荐页恢复后有 1 个活动 Feed、1 个标准活动卡片和 3 个视频，没有探针日志或探针错误。

这证明当前 Chrome + Tampermonkey 组合中，GM API 与页面传输 seam 可以共存。它不证明脚本绝对早于页面所有脚本、页面提前缓存的原始函数、首帧或首次音频采样。

### 2.3 后续 Feed 与 BGM 字段关联

真实键盘输入触发的后续推荐流请求为：

```text
GET /aweme/v1/web/tab/feed/
transport: XMLHttpRequest
content-type: application/json
```

本次响应摘要：

- 状态码 200，响应大小分桶为 `<=1MiB`；
- 有界扫描 863 个对象，未触发截断；
- 发现 5 个对象同时包含 `aweme_id` 与 `music.title`；
- 同对象内 ID 字段一致；
- 摘要不包含真实 ID 或 BGM 值。

因此，后续 Feed 的主实测路径是 XHR，不是原方案假设优先的 `fetch`。首版应以 XHR Adapter 为主路径，保留 `fetch` 兼容 seam；BGM 仍只允许从同一对象提取最小 DTO，并按 `awemeId/gid` 精确关联。无 ID、冲突或解析失败时 fail-open。

### 2.4 媒体结构和相对时序

Chrome 捕获到：

- 首个 `video` 约在 1902ms 被观察到；
- 该视频首个绘制帧约在 2055ms 被观察到；
- 首个标准活动卡片约到 3414ms 才被观察到；
- 首个视频在出现和首帧时，向上 16 层都没有可用的 `data-e2e` 语义祖先或视频 ID；
- 后续预加载视频可以在 `feed-video -> feed-item -> slideList` 祖先链中找到 19 位视频 ID；
- 捕获期间媒体原生状态为 `muted = true`，没有进行系统音频采样。

这直接否定了“仅凭当前活动卡片选择器即可在首帧前完成门控”的假设。预加载卡片仍可能提前判定，但首个媒体和激活时才出现的卡片不能承诺绝对零帧。

### 2.5 弹幕结构

Edge 和 Chrome 均观察到真实弹幕节点：

- 所有权单元是 `DIV[data-danmu-id]`；
- ID 为 19 位十进制字符串；
- 外层有三个直接子节点且存在显示文本；
- Chrome 复用感知探针观察到 3 个节点；
- 本次 30 秒窗口内没有观察到原地文本变化或节点复用。

因此可以冻结 `[data-danmu-id]` 所有权边界，但“未观察到复用”不能推出“不会复用”。实现仍需防御文本后填充和节点复用，并由 Node 回归和 Stage 3 实页验收覆盖。

### 2.6 `0.2.1` 窄范围浏览器回归

`0.2.1` 只复测本次安全修订涉及的行为，没有扩大 Stage 0 范围。为触发页面本来就会发起的 Feed 请求，捕获窗口内使用了一次真实浏览器 `ArrowDown`；该动作只作为请求刺激，不计入导航能力证据。

Chrome + Tampermonkey 实测确认：

- `GET /aweme/v1/web/tab/feed/` 依次产生 `xhr-candidate-open`、`send`、`settle` 和独立的 `xhr-candidate-shape`；
- `settle` 只记录状态 200 和 `application/json`，不再同步携带 `responseSummary`；
- 随后的独立 shape 事件成功从 `response-text` 有界解析，扫描 976 个对象且未截断，发现 6 个 `aweme_id + music.title` 同对象摘要；
- 报告不含完整 URL、真实视频 ID 或 BGM 值；
- 30 秒到期后状态为 inactive，只输出一份终局报告，`droppedEvents = 0`；
- 返回普通推荐页后有唯一活动 Feed 和标准活动卡片，没有新增探针报告或探针相关错误。

这完成了 `0.2.1` 的浏览器冒烟闭环，但仍不把诊断探针等同于正式脚本的传输实现验收。

## 3. 已否定或未闭环结果

### 3.1 绝对零帧

首帧早于标准活动卡片信号约 1.3 秒出现。现有 DOM 信号不足以证明命中视频绝不显示任何帧，高帧率录屏也尚未完成。

处置：从首版硬承诺中移除“绝对零帧”。正式实现以“对可提前识别的预加载卡片尽早门控；激活后命中时避免进入稳定画面；失败立即 fail-open”为目标，高帧率逐帧结果转入 Stage 2/Stage 5 人工验收。

### 3.2 绝对零可听音频与静音所有权

本轮没有系统音频采样，且捕获时视频本身已静音，因此不能证明首次音频采样前已被门控。探针按约束没有写入 `muted`，也没有验证站点/用户争用、条件恢复和下一卡是否受污染。

处置：不再以证明“绝对零音频”阻塞 Stage 0。Stage 2 只允许在 ownership token、争用检测、完整清理和下一卡不污染均通过源码测试后尝试临时 `muted`；真实音频和恢复路径转为人工验收。未通过时禁用媒体写入并降级为视觉过滤，不引入 `pause()/play()` 补丁。

### 3.3 可靠的可编程下一条

Edge 中真实 `ArrowDown` 曾得到 12/12 活动 ID 改变，可证明活动 ID 是完成确认信号；但 Chrome 浏览器控制键盘输入只得到 2/4 次改变，聚焦活动 Feed 后也只有 1/3 次改变，并一度出现活动 Feed 仍唯一但标准活动卡片暂时为 0 的状态。

点击下一张预加载卡片无效，Feed 也不是标准滚动容器。上述输入只是浏览器控制基线，不等于 Userscript 可用的合成事件或原生接口。

处置：可编程导航转为 Stage 2 能力闸门，不再阻塞 Stage 0 或 Stage 1。未找到可重复、可确认且不破坏原生状态的路径前，不实现或声明自动跳过；不以合成 `KeyboardEvent` 可用作为隐含假设。

### 3.4 其他未观察项

- 弹幕原地文本后填充与节点复用：本轮未出现；由防御性实现、Node 回归和 Stage 3 实页验收覆盖；
- 后台切换：浏览器控制切换未产生可信的 `visibilitychange` 证据；保留“后台立即 fail-open”契约，由控制器测试和人工验收覆盖；
- 250ms/100ms 和高帧率指标：仍是前台目标，不是当前已证事实；转入对应功能阶段和最终人工验收。

## 4. Stage 0 收敛判定

| 项目 | 证据状态 | 收敛处置 |
| --- | --- | --- |
| Tampermonkey 注入、GM API 与页面 seam 共存 | 已确认 | 可进入正式实现；最终脚本仍需实页回归 |
| 页面后续 Feed 传输 | 已确认 XHR 主路径 | 设计改为 XHR 主、`fetch` 兼容 |
| `aweme_id + music.title` 同对象 | 已确认 | 可实现最小 DTO 和 ID-only 关联 |
| 稳定活动 Feed/卡片、视频文本和弹幕外层边界 | 已确认 | 冻结第一版 Adapter 输入边界 |
| 当前活动卡片信号早于首帧 | 已否定 | 不再承诺依靠该信号实现绝对零帧 |
| 可编程下一条 | 未验证且基线不稳定 | 转为 Stage 2 能力闸门 |
| 系统音频、临时静音争用与恢复 | 未验证 | 转为 Stage 2/Stage 5 测试；失败即禁用媒体写入并降级承诺 |
| 弹幕复用、后台切换 | 本轮未观察 | 防御性实现 + 单元测试 + 人工验收 |
| 高帧率、250ms/100ms | 未验证 | 保留为测量目标，不作为 Stage 0 继续扩探针的理由 |

Stage 0 至此结束，其含义是“实现所需的关键结构与数据路径已有证据，剩余不确定性已有明确归属”，不是“三项过滤功能已经可用”。

后续阶段按以下边界推进：

- Stage 1 可以直接开始；
- Stage 2 在实现自动跳过前必须通过可编程导航能力闸门；媒体写入必须通过所有权、争用和恢复回归，否则只保留视觉侧降级；
- Stage 3 继续验证弹幕正文 Adapter、后填充和节点复用；
- Stage 4 可以基于已确认的 XHR Feed 路径实现透明观察；正式代码仍需单独完成传输透明性测试和实页回归；
- Stage 5 用高帧率录屏、系统音频采样和用户手工验收记录实际效果，不把未测指标表述为已保证。
