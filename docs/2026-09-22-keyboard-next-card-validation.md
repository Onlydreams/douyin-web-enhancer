# 后续卡片按键对照

## 已取得的 Chrome 实页证据

2026-09-22，已安装探针 0.2.0-test，正式脚本 DOM 标记为 0。
一次 early / focus-pair 实验在探针启动 2306ms 后向 body 发送 keydown + keyup；
文档聚焦，readyState=4，1x 播放，剩余墙钟时长约 76 秒。随后 5042ms
观察期间活动 ID 未变，结果为 not-confirmed。读取报告后对 body 发送一次浏览器
ArrowDown，下一次 DOM 检查活动 ID 已变，活动卡片数和播放视频数均为 1。

该结果证明这个样本中浏览器按键可以切换，但两个输入之间仍有时间差，且工具调用
未精确测量浏览器按键响应延迟。不能据此证明 isTrusted 检查、监听注册或动画锁是根因。
浏览器自动化按键也不能直接等同于用户物理键盘的完整事件序列。

## 新实验及安装产物

`tools/keyboard-navigation-probe.user.js` 0.3.0-test 新增显式 `next-card` 对照。
正式增强脚本未修改。此模式的目的为区分页面启动与后续卡片激活，不是给产品添加等待。

```text
https://www.douyin.com/?recommend=1&dwe_keyboard_probe=focus-pair&dwe_keyboard_wait=next-card
```

用户需完整替换 Tampermonkey 中的旧探针，保持正式脚本停用。扩展管理页由用户操作。
随后由代理在前台打开上述地址，在页面稳定后、30 秒内发送一次浏览器 ArrowDown。
探针只允许这一次无修饰键、非重复的可信方向键作为启动信号；3 秒内未观察到新卡片则退出。
新卡片稳定播放 1 秒后才发送一次合成按键组合，继续观察 5 秒。其他用户输入仍取消实验。
自动连播本身不会启动实验，初始人工切换不计入合成按键的切换次数。

报告包含 activationElapsedMs 和 dispatchElapsedMs，可以直接相减得到新卡片激活后
到合成按键的间隔；不记录视频 ID、正文、账号或媒体 URL。后台、输入框焦点、路由改变、
启动后的 Feed 根替换仍取消；所有等待有上限，结束后清理监听和计时器。

## 0.3.0-test 实页结果（2026-09-22）

Chrome 前台，正式脚本标记为 0；两个有效 next-card 样本均为 body 目标、
文档聚焦、readyState=4、1x 播放。每组只发送一次合成 keydown + keyup。

| 样本 | 新卡激活距探针启动 | 合成输入距新卡激活 | 剩余墙钟时长 | 结果 |
| --- | ---: | ---: | ---: | --- |
| 1 | 20931ms | 2167ms | 2050886ms | not-confirmed，ID 变化 0 |
| 2 | 27145ms | 1713ms | 540703ms | not-confirmed，ID 变化 0 |

触发要求是稳定播放 1 秒，加载和动画使实际激活到派发间隔大于 1 秒。
两组报告结束时 activePlaying=1、otherPlaying=0。样本 1 结束后，在同一视频
上发送一次浏览器 ArrowDown，随后 DOM 检查 ID 已变化，播放视频数为 1。
浏览器按键响应耗时未精确测量，也不将工具输入等同于用户物理按键。

另有一个 next-card 样本因 background 退出，eventCount=0；两个 settled
样本分别因 near-video-end 和 background 退出，eventCount 均为 0，均不计成功或失败。
因此本轮未取得新的有效 8 秒对照，不覆盖或改变前一天的历史结果。

结论：后续卡片也能复现早期合成按键失败，单纯的页面启动初始化假设不能解释
全部现象。尚不能确定是卡片就绪、事件处理路径、短时锁还是其他状态。
不以 isTrusted 差异直接断言根因，不将固定 8 秒等待或重试集成到正式过滤器。
后续需要观察站点实际处理的事件和导航入口，并区分输入目标、事件阶段与卡片就绪条件。
本轮仅记录诊断证据，正式脚本未修改。
