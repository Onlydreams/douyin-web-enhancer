# 2026-10-02 重复进入命中视频的导航排查

状态：修复、本地回归和 Chrome 同一卡片单步双向往返完成；用户已确认恢复原配置。正式版本 `0.0.6` 已按用户授权提交并推送。

## 故障与现场证据

Chrome + Tampermonkey 首页推荐流，用户报告向上经过命中视频能够跳过，再向下返回时停留在同一视频。代理使用真实滚轮往返复现活动命中卡 data-dwe-video-state=bypass；一轮向下操作也曾成功，故不是固定的向下方向错误。

产品日志为 next-control-unavailable。源码中此路径表示语义控件不可用，且原生入口没有返回经过验证的候选。浏览器工具提供的只读 DOM 表示不能读取真实 React 私有属性，最初返回的零 Fiber 属性不作为现场无 Fiber 的证据。浏览器安全策略禁止扩展管理页；为保留推荐队列，取消刷新计划，由用户在原页面 Console 执行经过离线验证的只读检查，代理读取日志并进行滚轮操作。

取得以下匿名化证据：

- 原命中卡已终局 bypass 时，一次检查得到 candidate-observed，上溯 108 层，唯一候选、当前树、Feed 归属及队列身份全部通过，证明入口并非始终不可用。
- 停留同一卡片时，约每 5 秒在直接当前树通过和 alternate 解析 current-path-limit 之间变化。
- 旧预算失败摘要：inspected=250、siblings=128、matchFound=false、remainingAncestors=17、kind=siblings。累计 2048 的总预算没有耗尽；退出时尚未找到目标分支。
- 同步只读对照只将每层兄弟预算改为 512，在同一页面得到 candidate-observed、currentTree=true、resolvedAlternate=true、唯一候选、scoped=true、indexMatches=true。动画中的身份失配样本仍为 candidate-unverified，没有因扩大遍历而跳过身份校验。
- 对照期间代理完成上/下往返，取得原脚本的成功导航样本；观察在 100 条变化摘要后自动清理。此观察证明算法校验差异，不能替代修复后的完整产品导航验收。

没有记录关键词、视频 ID、账号标识、URL 或页面原数据。未读取扩展编辑器逐字核对原安装源；用户执行 Console 检查和代理的日志/DOM 观察是不同证据层。

## 根因与修复

React 当前树切换后，需要沿已知祖先路径的 child/sibling 验证当前宿主。实页某层兄弟列表超过 128，旧预算提前退出，将有效入口误判为不可用，再把当前 epoch 终局放行。这使现象看起来与往返方向相关，实际取决于激活时需要解析哪棵树。

产品和已有原生探针的每层兄弟预算调整为 512；累计 2048 节点、128 层上溯、循环检测、唯一候选、宿主、身份、Feed 归属及最终派发前校验保持不变。仍只沿已知路径检查直接兄弟，不扫描完整 React 树。超过新预算继续 fail-open。

入口发现失败时记录已有发现函数的有界摘要。tools/create-reentry-inspection.js 从权威发现函数生成一次性 Console 检查或最多两分钟/100 条摘要的观察；没有网络请求、导航方法调用或页面对象改写，停止、后台、根替换和异常时清理。用于比较旧/新预算的临时代码已经移除。

## 修复后的实页验证

用户确认已用当前工作树全文替换现有 Tampermonkey 脚本并刷新。代理在新队列执行 18 次向下操作，观察到标准卡 allow，没有出现新的原生入口验证失败日志。由于没有遇到命中卡，此记录只说明正常导航，没有验收自动过滤。

用户确认临时追加现存相邻标准卡的公开标题词。随后代理观察到一张实际 block 卡，选择它作为往返样本；没有读取 GM 词库，不仅凭公开标题判断是哪类现有规则命中。

- 初次单次向下滚动，命中卡被自动越过，落到后方 allow 卡。
- 快速连续上/下输入时，有几次没有切换到预期卡片。虽没有停在命中卡，也没有降级日志，但这些样本不计为完整往返通过；未单独测量其节流/动画时序。
- 改为稳定后单次输入：向下越过命中卡到后方 allow 卡；向上进入同一命中卡时观察到 navigating，随后稳定落到前方 allow 卡；再次向下重新进入该命中卡，落回同一后方 allow 卡。
- 在检查中使用严格视频 ID 等值确认同一卡片及前后目的卡，结果只输出布尔值，不记录实际 ID。上述单步落点全部一致，没有新增原生入口验证失败或自动导航降级日志。
- 已停止滚动，用户确认仅移除临时追加词并保留原词库。代理收尾只读检查：页面 visible、唯一 Feed 根、同一后方标准卡 allow，没有原生入口验证失败或自动导航降级日志。词库恢复属于用户确认，没有逐项读取 GM 原始配置。

新安装来自用户全文替换并刷新的确认；代理没有读取扩展编辑器校验源码哈希。此为一张实际命中卡的原生导航往返定向证据，不能替代旧场景逐字重放、其他浏览器、音频/逐帧或全部计时边界验收。测试期间的快速连续翻动主要由代理寻找样本和往返输入触发，不能全部计为产品自动命中次数。

## 独立审查后的诊断观察修复

两个独立审查者确认同一 P2 问题：临时观察器直接在 MutationObserver 回调采样，忽略受影响节点，重复扫描全页。离线复核中，100 次不改变摘要的变化产生 300 次全局查询，没有新增摘要；未测量实际播放性能影响。

观察器现在只标记影响活动卡的属性或新增/移除节点，合并到既有 25ms 采样。活动卡查询限定于已验证 Feed，并缓存到相关节点变化后才重新查询；React 当前树仍每 25ms 只读检查，以覆盖无 DOM 变化的树轮换。全页根唯一性每秒复核，Feed 断开或不再匹配时在下一次采样停止；两分钟、100 条摘要、后台和异常的清理路径保留。

新增回归先在旧实现失败，再在修复后通过：1000 次无关变化不重新查询文档或活动卡；1000 次相关变化合并为一次 Feed 内查询；根唯一性按秒复核；活动卡移除、嵌套插入、属性变化及多卡歧义正确处理。补充观察器异常和 Feed 语义失效的清理分支。

本轮产品和生成器、两种生成代码语法检查通过，Node 单进程 265/265 通过；默认隔离运行仍因 spawn EPERM 失败。主脚本 SHA-256 保持上述值。本轮诊断工具修改尚未重新运行实页，不作为新增浏览器性能或导航证据。
