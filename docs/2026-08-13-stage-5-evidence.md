`0.4.9-test` 最小实页回归确认视频关键词、独立 BGM 命中、双向自动越过以及弹幕命中隐藏均生效；关闭弹幕规则后页面根和弹幕节点所有权已清理，未发现脚本控制台错误。随后连续导航与评论区加载后的抖音渲染进程增长到约 1GB 并失去响应，Tampermonkey 菜单 prompt 也无法出现。离线压力回归确认普通评论 `childList` 变更会触发弹幕、Feed 和 script 的多次后代选择器查询。

`0.4.10-test` 改为最多访问 64 个新增元素的有界遍历，并通过“无关评论节点零后代查询”回归。更新后的 Chrome + Tampermonkey 页面完成 12 次向下、6 次向上以及后续 60 次持续方向切换，共 78 次导航输入；过程中无页面操作超时，随后空闲 15 秒仍可读取 3 个 Feed 卡片。最大 Chrome 进程工作集采样从约 712 MB 增至 835 MB，没有复现此前约 1 GB 后失去响应的状态。回归结束后用户确认 BGM 编辑菜单 prompt 正常弹出。该证据支持定向崩溃回归通过，但短时进程采样不替代独立性能或 15 分钟生命周期验收。

`1.0.0-test` 随后完成 15 分钟长时推荐流主循环：分五段执行 24、24、24、12、16 次上下导航输入，共 100 次；每段结束后空闲 60 秒，均可继续读取页面，未出现控制器错误或 Feed 根歧义。单次操作包含固定等待，观察到的最长耗时约 10.6 秒；测试未取得浏览器 long-task trace，因此不把它归因于脚本。结束后点击站内“精选”时，页面控制先在 3 秒状态读取超时，等待恢复后又连续两次无法读取标签页；OS 进程仍报告响应，故证据结论为“推荐流主循环通过，SPA 切页失败/未闭环”，不是整项生命周期通过。

离线最小回归确认两个同步放大点：第一，64 元素上限原先按每个 `addedNode` 重置，一次含 100 个新增节点的 Mutation 批次会检查 100 个元素；第二，离开推荐路由后页面级 Observer 仍会检查 64 个新增元素寻找 Feed 信号。`1.0.1-test` 将预算改为整个 Observer 回调共享，并在非推荐路由立即停止 Feed 信号检查、清理推荐流所有权；两条回归由红转绿。

保存 `1.0.1-test` 后进行了定向 SPA 复测：推荐页基线可响应，进入“精选”约 3.0 秒，视频卡片和弹幕所有权标记均清零；首次返回推荐时，状态读取在 3 秒超时，等待 5 秒后再次读取仍超时并重置浏览器控制会话。OS 层 Chrome 进程仍为 `Responding=True`，最大进程工作集约 823 MB。因此 `1.0.1-test` 实页复测失败，不能作为修复完成证据。进一步离线回归确认，一个 Observer 回调仍可遍历任意数量的 Mutation 记录；`1.0.2-test` 对 Feed 根和全局生命周期回调增加每批 64 条记录硬上限，同时保持弹幕观察器不截断以避免漏渲染。新增记录预算回归已由红转绿，真实 SPA 复测待保存 `1.0.2-test` 后完成。

保存 `1.0.2-test` 后再次定向复测：进入“精选”仍约 3.0 秒；首次返回推荐的 3 秒状态读取再次超时，Chrome 最大进程工作集由复测前约 587 MB 升至约 815 MB。证据继续指向返回推荐时的同步工作。调用链检查发现健康检查在每次路由变化时调用 `syncBgmObserver(true)`，会遍历 `document.scripts`，并对每个脚本执行全文标记搜索；SPA 返回推荐时传输观察器已经能够捕获新的 Feed 响应，无需再次全量扫描内联脚本。`1.0.3-test` 将路由健康检查改为只同步传输观察器，不扫描既有脚本；首次启动、配置更新和新增 script 的解析路径保留，并增加回归测试。

对 `1.0.3-test` 的对抗式审查确认五项可稳定复现的问题：虚拟列表驱逐卡片后 `ownedCards` 未释放；控制器级 fail-open 后 BGM 传输仍运行且 `started` 仍为真；BGM DTO 遍历无时间预算；预测导航偏离会把用户手动导航计入脚本跳过；弹幕-only 配置更新会重扫内联 BGM 脚本。五条回归均先红后绿。`1.0.4-test` 对应增加 Feed `removedNodes` 所有权清理、彻底停止故障控制器、8ms DTO 遍历截止、预测偏离不计数和按 BGM 配置变化决定脚本扫描。浏览器原生 `Response.text()` 与同步 `JSON.parse()` 不能由脚本抢占，文档已将承诺收窄为文本长度检查和 DTO 遍历时间预算。

`1.0.4-test` 复审确认上述五项均已正确修复，同时发现运行时停止后菜单仍显示开启、活动 epoch 卡异常驱逐时可能遗留旧 epoch，以及等价规范化 BGM 配置仍触发脚本扫描。`1.0.5-test` 增加三条先红后绿回归：配置提交在 `updateSettings` 失败后只尝试一次 `start(nextSettings)`；恢复失败时三个状态菜单均显示“运行已停止”而持久化设置不回滚；活动卡驱逐会先退休 epoch；BGM 是否变化按 `enabled + compiledKeywords` 比较。

`1.0.5-test` 复审确认修复未退化，并指出停止态状态菜单点击会顺带翻转开关、成功恢复前会先记录一条误导错误。`1.0.6-test` 增加两条先红后绿回归：菜单动作先读取最新控制器快照；停止态点击状态菜单只调用一次 `start(settings)`，不写存储、不翻转启用状态；停止态编辑配置在持久化后直接 `start(nextSettings)`，不调用必然失败的 `updateSettings`，成功恢复不记录错误。瞬时故障仍采用静默自愈，持久故障继续显示“运行已停止”。

保存 `1.0.6-test` 后执行首次 SPA 往返实测：推荐页基线 Feed 根唯一，产品脚本拥有 1 张视频卡和 2 条弹幕；进入“精选”约 2.97 秒，Feed 根和脚本所有权均清零。首次返回推荐后，3 秒状态读取再次因页面控制超时失败。Chrome 最大进程工作集由约 539 MB 升至约 668 MB，OS 层仍为 `Responding=True`。随后用户人工确认页面上的刷新操作也无法点击，只能关闭全部 Chrome 窗口；因此这次不再仅记为自动化控制超时，而是用户可见的浏览器失去交互响应。该症状与 `1.0.1-test`、`1.0.2-test` 一致，说明连续离线修复尚未改变现场结果；继续修改业务代码已缺少归因证据。下一步必须在全新 Chrome 会话中先完全禁用产品脚本，再打开抖音推荐页并执行相同往返作为 A/B 对照。浏览器安全策略禁止代理操作 `chrome-extension://` 管理页，因此该开关需要用户手工完成。

用户关闭全部 Chrome 窗口、重新启动并手工禁用产品脚本后，完成了相同 A/B 对照。新推荐页中产品脚本所有权标记为 0；进入“精选”约 2.52 秒，返回推荐约 5.74 秒，随后轻量页面状态读取耗时约 24ms，页面保持可交互，未复现刷新无法点击或必须关闭全部窗口的故障。对照表明抖音/Chrome SPA 自身存在数秒级切换延迟，但用户可见的升级性失去响应与启用产品脚本高度相关；尚不能据此定位到视频、弹幕、BGM 或生命周期模块。下一步改为单变量模块隔离，不再重复全功能启用的往返测试。

随后重新启用产品脚本，但关闭视频、弹幕和 BGM 三类规则，以隔离 bootstrap 与基础路由生命周期。推荐页无视频或弹幕所有权标记；进入“精选”约 2.45 秒，返回推荐约 5.74 秒，返回后的轻量状态读取约 26ms，页面保持可交互。该结果与完全禁用产品脚本的对照基本一致，可排除 bootstrap 和三类规则均关闭时的基础路由生命周期为单独主因；故障进一步收敛到至少一个功能模块的启用路径或多模块组合，后续使用不命中测试词逐项启用。

单独启用视频关键词并使用不命中测试词后，推荐页可见 2 张视频所有权卡片，状态为 `bypass/allow`；进入“精选”约 2.47 秒且所有权清零，返回推荐约 5.74 秒，返回后的轻量状态读取约 24ms，并正常重建 1 张 `allow` 卡片。页面保持可交互，故视频模块单独启用未复现故障；后续优先隔离 BGM 网络包装，再隔离弹幕动态观察。

关闭视频和弹幕、单独启用 BGM 并使用不命中测试词后，尚未执行 SPA 导航，推荐页基线状态读取已持续超过约 30 秒并超时；同一读取在规则全关和仅视频状态均可完成。OS 层 Chrome 进程仍报告响应，最大工作集采样约 780MB。离线调用链与先红后绿回归确认，运行中开启 BGM 会调用 `syncBgmObserver(true)`，同步读取当前页全部历史 script 正文；`1.0.7-test` 将配置更新改为只同步网络观察器，不扫描历史 script。首次启动兼容扫描、全局 Observer 对新增 script 的增量处理和 Feed 响应捕获均保留。该修复尚待保存到 Tampermonkey 后按相同“仅 BGM”场景实页复测；若仍阻塞，再隔离传输包装与响应解析。

保存 `1.0.7-test` 后，“仅 BGM”推荐页基线从超过 30 秒超时恢复为约 5.79 秒可读，2 张视频卡均为 `allow`；进入“精选”约 2.46 秒且所有权清零，证明取消运行中历史 script 全扫修复了第一段阻塞。随后返回推荐约 9.70 秒才完成，比禁用脚本、规则全关和仅视频对照的约 5.74 秒多约 4 秒；返回后的轻量状态读取继续阻塞超过 20 秒并最终超时。因此 `1.0.7-test` 仍未通过 SPA 验收，剩余故障已收敛到 BGM 观察器重启后新 Feed 响应的读取、解析或元数据回调链；不得把首段修复表述为整体问题已解决。

离线高扇出匿名 fixture 随后复现第二个预算缺口：`extractBgmMetadata` 的 `maxNodes=5` 时，单个 10,000 项数组仍被 `Object.values()`/子项压栈路径完整读取 10,000 次，因为预算只在弹栈处理节点时检查。`1.0.8-test` 改为按 `maxNodes - scanned - stack.length` 计算剩余槽位，数组和对象只枚举剩余预算允许的子项，超出即标记 `truncated` 并 fail-open；回归由“读取 10,000 项”转为不超过 5 项。该修复位于 SPA 返回时新 Feed DTO 的真实处理路径，但尚未实页验证；原生 `Response.text()` 与同步 `JSON.parse()` 仍不可抢占，若 `1.0.8-test` 仍卡死，需继续缩小或取消字符串响应解析路径。

用户手工更新并测试 `1.0.8-test` 后再次确认整页卡死并关闭浏览器，故高扇出预算缺口虽属真实问题，却不是现场故障的充分根因。结合禁用脚本、规则全关和仅视频对照均通过，剩余共同变量为 BGM 页内传输包装及响应克隆/解析链。`1.0.9-test` 以“失败时不破坏原站”为优先，从产品控制器移除 BGM fetch/XHR 包装和历史 script 扫描，仅保留全局 MutationObserver 已观察到的新增 QuickPlayer script 有界解析；离线回归确认产品运行路径不创建传输观察器、不读取历史 script，且新增 QuickPlayer 元数据仍可精确关联并走统一导航。该变更主动降低 BGM 覆盖率，尚待只验证 SPA 不再卡死。

用户指出 `1.0.9-test` 的止损方案实质削弱了 BGM 功能，不应作为最终修复。随后建立最小离线反馈环：两个候选 Feed 响应的正文读取均保持未完成时，旧传输实现会启动两次 clone；扩展到 128 个响应时会等比例启动 128 次，证明正文读取没有单飞或背压边界。`1.0.10-test` 恢复控制器的 XHR/fetch Feed 数据源，全传输共享一个正文处理槽；已有任务未完成时，新候选响应不读取正文并 fail-open，正文就绪后的 JSON 解析延后到独立任务。单飞槽跨 `stop() -> start()` 保留到旧正文真正结束，避免 SPA 往返重新叠加未完成 clone；运行令牌仍阻止旧元数据进入新会话。最小红灯由 `2 !== 1` 转为通过，同时保留调用语义、迟到运行隔离、DTO 预算和新增 QuickPlayer 增量解析回归。该结果证明无界资源放大已被锁住，但尚不能证明它是实页卡死的唯一根因；`1.0.10-test` 仍需仅 BGM 与 SPA 往返人工复测。

## 隐私与公开检查

- Userscript 只声明 GM 本地存储和菜单权限，无 `GM_xmlhttpRequest`、`@connect`、Cookie、下载、剪贴板或通知权限；
- 产品脚本不发送额外请求，不点击会改变账号状态的控件；
- 关键词不写入页面 DOM、网络或日志；
- 仓库扫描未发现本机用户路径、认证头、真实 Token、Cookie、密码或账号标识；
- 测试中的 `token=secret` 是验证脱敏器的合成输入，不是真实凭据；
- fixture 和报告只保留匿名结构与完成验收所需的最小证据。

## 已知限制与未验证项

- 视频/BGM 自动跳过只支持抖音首页“推荐”标准视频流；
- 弹幕过滤只覆盖存在可识别 `[data-danmu-id]` 节点的视频页面；
- 不承诺直播、图文、短剧、放映厅、搜索、个人主页、评论区、广告或游戏推广卡片；
- 最终版本未在 Edge、Firefox、Violentmonkey 或 Safari 复测；
- Network 面板无新增请求、独立性能 trace、系统音频采样和高帧率零帧仍未取得独立人工证据；当前 Chrome 会话的 15 分钟推荐流与 3 次 SPA 往返已通过，后台标签页和真实根异常替换仍未独立验收；
- `1.0.0-test` 的 15 分钟推荐流主循环通过，但其后的 SPA 切页超时；禁用脚本、规则全关和仅视频对照通过；`1.0.7-test`、`1.0.8-test` 的 BGM 修复后仍卡死；`1.0.10-test` 恢复有单飞背压的传输路径后，真实 BGM 命中、仅 BGM、三模块组合及 15 分钟 SPA 生命周期均通过，当前 `0.0.1` 沿用相同实现；
- `1.0.10-test` 在已有 Feed 正文任务未完成时会放弃重叠响应，属于明确的稳定性 fail-open；是否造成可见漏判需在真实 Feed 节奏下复测；
- 当前不写 `muted`，不调用 `pause()/play()`，不承诺绝对零音频或零帧。

这些缺口不冒充已通过。产品脚本单变量模块隔离、SPA 失去响应修复、真实 BGM 命中以及 15 分钟定向生命周期已经闭环；当前产物仍标为发布候选。正式发布前仍需补齐 Network 无新增请求和独立性能 trace，并决定后台标签页与真实根异常替换是补测还是作为已知验收缺口记录；系统音频与高帧率零帧因媒体写入未启用，不作为当前能力承诺。
