# 抖音 Web 增强 Userscript 技术方案

> 状态：Design only，尚未进入实现
> 日期：2026-08-13
> 目标产物：单文件 Tampermonkey Userscript
> 首版范围：抖音 Web 首页“推荐”标准视频流
> 本次修订：将“无感过滤”提升为首版行为契约

> 对抗式审查处置：2026-08-13 完成独立审查；采纳 ID-only BGM 关联、媒体争用检测、先失效后清理、终局决策语义、前台计时和 Stage 0 注入时序门槛。`pause()/play()` 不进入首版默认路径。

## 1. 决策摘要

本项目参考 `zhihu-web-enhancer` 和 `xiaohongshu-web-enhancer` 的交付形式，采用：

- 单文件 Userscript，同时作为源码和可安装产物；
- 零构建、零第三方运行时依赖；
- Node 内置测试运行器；
- Tampermonkey 菜单和 GM 本地存储；
- 真实 DOM 优先、站点易变细节集中隔离；
- 只改变本地显示和播放流程，不点击“不感兴趣”，不提交推荐反馈；
- 不调用抖音私有接口，不发送额外网络请求；
- 读取页面本来就会接收的 Feed 数据，以支持 BGM 名称识别；
- 在视频或弹幕绘制前完成可判定内容的过滤；需要等待 BGM 时使用有界逐卡门控和临时音频抑制。

三个功能分别维护独立开关和独立词表：

1. 视频关键词命中后自动进入下一条；
2. 弹幕关键词命中后只隐藏对应弹幕；
3. BGM 名称命中后自动进入下一条。

关键词首版只支持大小写不敏感的子串匹配，不支持正则表达式、通配符或布尔表达式。

“无感”在本方案中的工程定义是：在可见前台标签页中，命中视频不产生可听音频、不进入稳定画面，命中弹幕不先显示再消失；已预加载并可判定的连续命中卡片直接越过。无法判定时目标门控上限为 250ms，随后 fail-open。这里不承诺所有未知页面状态、后台调度或注入降级下数学意义的绝对零帧。

## 2. 参考项目中复用与不复用的设计

### 2.1 复用的设计

从两个参考项目复用以下约定：

- 保持单文件、直接安装、无构建步骤；
- bootstrap 负责 GM 存储和菜单，页面控制器不直接读取 GM 配置；
- 关键词在配置变化时统一规范化、去空、去重和编译，不在每个节点上反复读取存储；
- 菜单动态显示“未配置 / 已开启 / 已关闭（已保存）”以及有效词数；
- MutationObserver 只收集受影响节点，不在每次回调中全量扫描整个文档；
- 页面根替换、SPA 路由变化、关闭功能和控制器停止都有明确清理路径；
- 只恢复脚本自己拥有的 DOM 状态；
- 页面选择器、动态加载和真实交互必须在最新 Tampermonkey 副本上实测，Node 测试不能代替实页验证。

### 2.2 不直接复用的设计

以下实现与抖音页面模型不匹配，不应照搬：

- 知乎脚本中分散在多个页面分支里的独立 Observer；抖音首版应集中到一个生命周期控制器；
- 小红书瀑布流的布局接管、列识别和 transaction；抖音只切换视频，不需要重排 Feed；
- 知乎通过 `display:none` 隐藏完整内容卡片；抖音视频命中后应切换下一条，而不是从虚拟列表中删除卡片；
- 依赖混淆 CSS 类名的定位；抖音适配优先使用 `data-e2e`、语义属性、DOM 关系和数据字段。

## 3. 当前实页证据

2026-08-12 在登录状态下检查 `https://www.douyin.com/?recommend=1`，确认：

| 对象 | 当前可用信号 | 结论 |
| --- | --- | --- |
| Feed 根 | `[data-e2e="slideList"]` | 可作为推荐流发现锚点 |
| 视频卡片 | `[data-e2e="feed-item"]`、`[data-e2e="feed-video"]` | 可限定标准视频卡片 |
| 视频描述 | `[data-e2e="video-desc"]` | 当前包含标题、描述和话题文本 |
| 当前视频 | 视口中心卡片、播放中的 `video`、卡片几何 | 需组合判断，不能依赖单个 class |
| 弹幕输入 | `[data-e2e="danmaku-container"]` | 可定位当前播放器弹幕区域 |
| 弹幕节点 | `[data-danmu-id]`，外层存在 `.danmu` | 弹幕是 DOM，不是 Canvas，可逐条过滤 |
| 视频标识 | 后代链接中的 `aweme_id` / `gid`（部分卡片） | 可作为精确关联的第一优先级 |
| BGM 数据 | 视频对象中的 `music.title`、`music.musicName` | 名称可读，但通常不直接显示在卡片 DOM |
| 下一条行为 |真实 `ArrowDown` 已验证会切换下一条 | Userscript 内仍需验证可编程切换方式及确认机制 |

页面还存在大量混淆 class，例如弹幕和播放器内部 class。这些 class 只能作为当前结构的辅助信号，不能成为核心接口。

## 4. 目标与非目标

### 4.1 首版目标

- 支持抖音首页推荐流的首屏、预加载卡片和继续下滑；
- 视频关键词匹配标题、描述和话题，不匹配作者、评论、章节摘要或页面其他文字；
- 弹幕关键词只匹配每条弹幕的显示文本；
- BGM 关键词只匹配 `music.title` 和 `musicName`，不把作者字段单独加入匹配范围；
- 三组规则可以独立开启、关闭、编辑和清空；
- 弹幕配置变化立即作用于当前弹幕和后续弹幕；视频/BGM 配置不突袭跳过已稳定播放的当前视频，从下一次激活开始生效；
- 对预加载视频提前形成决策，使已知命中内容不成为稳定活动卡片；
- 命中视频不产生可听音频，命中弹幕不出现“先显示后隐藏”；
- BGM 元数据尚未就绪时，允许对可见前台中即将激活或当前卡片进行目标最长 250ms 的视觉与音频门控；
- 对无法识别或无法可靠关联的数据 fail-open，即放行而不是猜测；
- 所有观察器、计时器、响应拦截包装和 DOM 所有权都可停止或恢复；
- 不在 DOM、日志或网络中暴露用户的完整关键词列表。

### 4.2 首版非目标

- 直播卡片；
- 图文、短剧、放映厅、搜索结果、个人主页和评论区；
- 未经实测的“精选”“关注”“朋友”等频道；
- 广告卡片和游戏推广卡片的专门处理；
- 点击“不感兴趣”或修改账号推荐画像；
- 读取历史记录、Local Storage、Cookie 或额外账号数据；
- 正则表达式、词组逻辑、云同步、命中统计或导入导出；
- 在所有浏览器调度、网络延迟、特殊卡片和未来页面实现中保证绝对零帧；
- Firefox、Violentmonkey 和 Safari 的首版兼容性承诺。

后续页面只有在取得真实 DOM 和数据证据后，才增加新的页面 Adapter；不能仅因选择器看起来相似就扩大支持范围。

## 5. 行为契约

### 5.1 关键词语义

三组关键词采用同一纯匹配模块：

1. 输入格式为 `关键词A|关键词B|关键词C`；
2. 对每项执行 Unicode NFKC 规范化、连续空白压缩和首尾去空；
3. 使用 `toLowerCase()` 做大小写不敏感匹配；
4. 按规范化结果去重；
5. 空项忽略；
6. 使用普通子串匹配；
7. Emoji 保持原样，不主动删除变体选择符；
8. 关键词数量以规范化、去空、去重后的结果为准。

不把词表写入页面 DOM。菜单只显示有效词数，不展示具体词。

### 5.2 视频关键词

匹配输入优先级：

1. 当前视频元数据的 `itemTitle`、`desc`、`caption`；
2. 当前活动卡片 `[data-e2e="video-desc"]` 的可见文本；
3. 元数据尚未就绪时可先使用 DOM 结果，后续元数据到达后只补充尚未决定的字段。

作者名、互动数字、章节摘要、AI 摘要、游戏推广文本和页面其他卡片不得进入匹配输入。

一旦任一视频关键词命中，不需要等待 BGM 元数据，立即请求切换下一条。

### 5.3 弹幕关键词

- 观察范围限定到当前活动视频卡片内的弹幕层；
- 以 `[data-danmu-id]` 为弹幕所有权单元；
- 新节点、文本后填充和节点复用都要重新判断；
- 命中后添加脚本专属属性，由专属 CSS 隐藏；
- 未命中或配置关闭时，只移除脚本添加的属性；
- 不删除弹幕节点，不修改抖音弹幕开关，不影响用户发送弹幕；
- 点赞数、菜单文字等辅助文本应在实测后从弹幕正文提取函数中排除；无法可靠分离时，以完整渲染文本匹配并记录这一边界。

### 5.4 BGM 名称

BGM 过滤必须同时满足：

1. 已获得当前视频的 `music.title` 或 `musicName`；
2. 元数据能可靠关联到当前卡片；
3. 名称命中 BGM 词表。

关联只有一条允许路径：卡片取得的 `aweme_id` / `gid` 必须与元数据 `awemeId` 精确相等。无 ID、ID 冲突或同一 ID 出现不一致元数据时一律放行并停用该记录的 BGM 判定。

首版明确禁止：

- 使用描述 + 作者做 fallback；
- 使用当前缓存中的“唯一候选”推断身份；
- 按 Feed 数组或 DOM 顺序猜测当前视频；
- 仅凭 BGM 名称、作者或播放 URL 反推视频身份。

只有 BGM 规则开启而元数据暂未到达时，才进入有界等待：

- 预加载且尚未接近激活的卡片可以继续等待元数据，不启动可见门控期限；
- 可见前台标签页中，卡片成为下一激活候选或当前活动卡片时，启动不可重置的目标 250ms 决策期限；
- 等待期间保持该卡片视觉门控，并临时抑制其音频；
- 期限内取得可靠元数据后立即形成 `allow` 或 `block`；
- 达到期限仍无法可靠关联则形成当前激活周期的 `bypass` 并放行；
- `bypass` 后到达的迟到元数据不得让正在观看的视频突然被跳过；只有该卡片离开并在新的激活周期返回时才允许重新判定；
- 不无限轮询，也不因 BGM 缺失持续保持空白。

### 5.5 自动下一条

切换动作由一个内部函数集中处理，不允许视频关键词和 BGM 模块各自滚动页面。

流程：

1. 为当前卡片生成稳定决策键，优先使用 `awemeId`；
2. 将命中卡片保持在视觉门控状态，并暂停或静音当前卡片内正在播放的视频；
3. 选择 DOM 中紧邻的下一张标准 Feed 卡片；
4. 使用实测通过的原生滚动或播放器切换方式请求进入下一条；
5. 等待“活动卡片已经改变”的确认信号；
6. 确认前禁止发起第二次切换；
7. 超时仍未改变时最多重试一次，之后 fail-open 并显示简短提示，避免连续误跳。

实现阶段必须分别验证：

- `nextCard.scrollIntoView()` 是否触发抖音正确更新播放状态；
- 对 Feed 根滚动是否比合成键盘事件可靠；
- 合成 `KeyboardEvent` 是否被站点接受。

最终只保留一个主路径和一个有确认条件的 fallback，不能同时触发多个动作。

为防止规则过宽或错误关联造成无限翻页，设置跳过熔断：

- 15 秒内最多连续跳过 12 条；
- 用户在一条允许视频上停留 3 秒后重置计数；
- 触发熔断后本页暂停自动跳过并提示用户检查规则；
- 弹幕过滤不受该熔断影响；
- 用户修改任一视频/BGM 配置后可解除熔断。

### 5.6 无感过滤契约

无感过滤由控制器内部的“逐卡决策门”统一完成，不为视频关键词、BGM 和导航建立三套互相竞争的门控。

每张标准视频卡片在每个配置 revision 和激活 epoch 中只能处于以下一种状态：

```text
pending -> allow
pending -> block -> navigating
pending -> bypass
```

- `pending`：尚未形成最终决策；媒体画面不可见，音频被临时抑制；
- `allow`：允许显示和播放；
- `block`：保持门控并交给统一导航流程，不允许先揭示再跳过；
- `navigating`：已经请求下一条，等待活动卡片改变；
- `bypass`：期限到达或发生不可恢复的不确定性，按 fail-open 显示和播放。

`allow`、`block` 和 `bypass` 对当前激活 epoch 都是终局状态。终局后到达的视频元数据或 BGM 元数据不得翻转当前状态；只有卡片离开后再次激活、Feed generation 变化或用户配置产生新的 revision，才创建新 epoch。已经进入 `navigating` 的旧 epoch 只允许完成或失败，不被新配置复用。

完整转换约束：

```text
pending -> allow | block | bypass
block -> navigating
navigating -> retired
allow | bypass -> retired
任意非 retired 状态 --根失效/页面隐藏/停止--> retired
```

不存在 `allow -> block`、`bypass -> block` 或旧 epoch 回到 `pending` 的转换。

#### 5.6.1 视频预判

1. Feed 新卡片进入 DOM 后，同步提取描述并创建决策记录；
2. 在卡片激活前，DOM 与已到达元数据都可以补充 `pending` 的输入快照；
3. 若任一已取得的视频文本字段命中，直接进入 `block`，不等待 BGM；
4. 卡片成为激活候选时，以当时可用的 DOM/元数据快照完成视频文本终判；此后迟到的视频文本不作用于本 epoch；
5. 若视频关键词未命中且 BGM 功能关闭，进入 `allow`；
6. 若 BGM 功能开启，则只按精确 `awemeId` 查询已缓存元数据；可判定时立即进入 `allow` 或 `block`；
7. 无元数据的离屏预加载卡片保持逻辑 `pending`，但不启动计时器；
8. 下一激活候选进入决策窗口时才应用目标最长 250ms 的可见门控；
9. 配置 revision 变化只重判尚未稳定激活的卡片；当前 `allow` / `bypass` 视频保持到离开，避免观看中途突袭跳过；
10. 新 revision 必须为受影响候选创建新的 epoch，旧 epoch 先标记 `retired`，禁止复用旧异步任务。

#### 5.6.2 视觉门控

- `document-start` 同步读取配置；只有视频或 BGM 规则实际生效时才安装视频门控 active class；
- CSS 只门控当前脚本识别为标准视频的媒体内容，不隐藏全站导航和控制栏；
- 卡片使用脚本专属决策属性，未知或特殊卡片应在同一任务内标记 `bypass`；
- 已知 `block` 卡片在导航确认前始终保持不可见；
- `allow` / `bypass` 必须一次性解除视觉门控和媒体门控；
- 门控失败、Observer 失败或 250ms watchdog 到期时必须 fail-open，不能让 Feed 长期空白。

允许内容在 BGM 数据缺失时可能看到不超过 250ms 的中性背景或上一稳定画面；不得展示待判定视频的帧。Stage 0 需要在真实页面确认哪一种视觉承接不会破坏抖音虚拟列表和切换动画。

#### 5.6.3 音频门控

- Stage 0 验证通过后，才把 `document-start` 捕获阶段的媒体 `play` / `playing` 观察视为可用的早期信号；不能仅从注册时机推导为已覆盖首次音频采样；
- 首版默认只通过媒体元素的临时 `muted` 抑制 `pending` / `block` 音频，不调用 `pause()`，也不负责调用 `play()` 恢复；
- 每次写入创建内部 ownership token，记录 generation、配置 revision、激活 epoch、媒体元素身份、原始 `muted` 和脚本写入值；
- 门控期间监听目标媒体的 `volumechange` 及活动卡片变化。脚本自己的同步写入必须用 token 明确标记；任何无法归因于当前 token 的媒体变化都视为所有权争用；
- 无争用且 token、generation、epoch 和元素身份仍有效时，`allow` / `bypass` 才可把 `muted` 恢复为原值；
- 出现争用、元素被站点复用、根失效或属性状态不符合预期时，不根据“值仍相等”猜测所有权，不主动恢复该元素；立即撤销视觉门控、停止该 epoch 的自动跳过，并等待站点在新的活动卡片上建立原生媒体状态；
- Stage 0 必须验证保守不恢复路径不会污染下一张允许视频；若会污染，媒体元素原地修改方案不成立，应改用不触碰站点媒体状态的音频输出门控方案或降低“零音频”承诺；
- 不写入抖音持久音量设置，不点击静音控件，不改变下一条允许视频的用户音量。

#### 5.6.4 弹幕首绘门控

- 弹幕规则生效时，为当前弹幕根启用脚本专属 active class；
- CSS 默认隐藏该根内尚未具有脚本决策属性的 `[data-danmu-id]`；
- MutationObserver 在浏览器下一次绘制前同步提取文本并标记 `allow` 或 `block`；
- 文本异步后填充的节点保持 `pending`，同时观察 `characterData`；
- 单条弹幕等待超过 100ms 或正文无法可靠提取时标记 `bypass`；
- Observer、根替换或控制器异常时先撤 active class，再清理专属属性，禁止让未决弹幕永久隐藏。

#### 5.6.5 连续命中

- 导航规划器优先检查 DOM 中已经预加载的后续卡片；
- 连续的已知 `block` 卡片不得逐条揭示；
- 如果真实页面验证支持直接定位，直接导航到第一条已知 `allow` 卡片；
- 如果抖音必须逐条推进，则逐条请求原生切换，但所有中间 `block` 卡片继续保持视觉和音频门控；
- 遇到第一个未决卡片时停止向后猜测，进入该卡片的有界决策窗口；
- 原有“15 秒内最多连续跳过 12 条”熔断继续生效。

#### 5.6.6 无感验收阈值

首版以以下可观察指标作为验收标准：

1. 命中视频产生的可听音频为 0；
2. 已在进入视口前形成 `block` 的视频不出现可识别画面；
3. 激活时才命中的视频不得进入稳定画面，目标是不超过一个绘制帧；
4. 命中弹幕不出现“先显示后隐藏”；
5. 可见前台标签页中，BGM 未决卡片目标门控上限为 250ms，弹幕未决目标上限为 100ms；
6. 连续命中后落在第一条可可靠判定的允许内容；
7. 识别失败不会导致持续空白、静音残留、播放器停住或无法继续浏览。

“目标不超过一个绘制帧”必须通过真实浏览器录屏或逐帧检查验证，不能由 MutationObserver 代码路径推断为已通过。“零可听音频”同样是 Stage 0 待证假设；未通过时必须降低承诺，不能通过增加未经验证的 `pause()/play()` 补丁掩盖。

## 6. 模块与 seam

### 6.1 外部 interface

Userscript IIFE 内设置一个深模块：

```text
createDouyinEnhancerController({ runtime, logger })
  -> start(initialSettings)
  -> updateSettings(nextSettings)
  -> stop()
```

调用者只需要理解三种操作。控制器隐藏以下实现：

- 推荐路由判断；
- Feed 根发现和替换；
- 当前活动卡片选择；
- 视频文本提取；
- 逐卡决策门、配置 revision 和激活 epoch；
- 视觉门控、ownership-token 临时音频抑制、争用检测及条件恢复；
- 弹幕观察和所有权恢复；
- 页面内嵌数据解析；
- Fetch/XHR 透明观察；
- 视频与元数据关联；
- 切换确认、重试和熔断；
- Observer、timer 和 SPA 生命周期清理。

bootstrap 负责 GM 存储、菜单注册和初始设置读取。控制器不得直接调用 `GM_getValue`、`GM_setValue` 或注册菜单。

### 6.2 内部 runtime seam

生产和测试需要两个 Adapter，因此 runtime seam 是真实 seam。它按能力分组，不把十几个浏览器函数平铺到控制器 interface：

```text
runtime.document
runtime.location
runtime.observers
runtime.scheduler
runtime.routeSignals
runtime.navigation
runtime.pageTransport
runtime.mediaGate
```

- `observers` 创建 MutationObserver 和 IntersectionObserver；
- `scheduler` 提供时间、动画帧和计时器；
- `routeSignals` 合并 `urlchange`、`popstate` 和 `pageshow`；
- `navigation` 请求下一条并提供活动卡片变化确认；
- `pageTransport` 安装和卸载只读响应观察；
- `mediaGate` 对待判定媒体执行可恢复的静音/暂停，并报告所有权冲突。

测试 Adapter 使用确定性时钟、假 DOM 和可控响应；生产 Adapter 使用浏览器对象。

### 6.3 首版不建立公开页面 Adapter

首版只有首页推荐流一种经过验证的页面实现，因此页面函数先作为控制器内部函数：

```text
isSupportedRoute()
findFeedRoot()
collectFeedCards(root)
findActiveVideoCard(root)
extractVideoText(card)
extractAwemeId(card)
findDanmakuRoot(card)
extractDanmakuText(node)
```

出现第二个已验证页面后，再把这些函数提取为页面 Adapter。提前抽象只会形成浅模块，并让未经验证的页面差异进入共享逻辑。

### 6.4 纯规则模块

```text
compileKeywords(rawValue) -> CompiledKeywords
matchesKeywords(text, compiledKeywords) -> boolean
evaluateVideo({ textFields, musicFields }, settings) -> Decision
```

`Decision` 只有 `allow`、`block`、`pendingMetadata` 三种结果，并携带类别，不携带完整用户词表。

### 6.5 元数据采集模块

该模块只输出最小 DTO：

```text
{
  awemeId,
  desc,
  itemTitle,
  caption,
  authorNickname,
  musicTitle,
  musicName
}
```

不保留视频 URL、认证字段、Cookie、Token、完整响应或账号数据。

缓存为有上限的内存 LRU，建议最多 500 条；离开支持路由或控制器停止时清空，不写入 GM 存储。

## 7. BGM 数据采集设计

### 7.1 执行上下文

首版面向 Tampermonkey 5.x + Chromium，使用：

```text
@run-at document-start
@sandbox raw
```

Tampermonkey 官方文档将 `raw` 定义为请求页面 `MAIN_WORLD`，但 `document-start` 只表示尽可能早注入，不能据此保证早于页面保存原始 `fetch`、首帧或首次音频采样；`raw` 也可能因环境限制回退。以下均为 Stage 0 硬门槛，而非既定事实：

- 确认脚本实际运行的 world；
- 确认 GM 菜单和存储在该 world 中可用；
- 确认包装安装早于抖音保存或使用传输函数；
- 记录脚本注入、首个 Feed 请求、首个媒体事件、首帧和首个音频采样的相对时序；
- 验证 CSP、Tampermonkey 注入模式变化及浏览器升级时的降级行为。

任一硬门槛不满足时，不启用对应传输观察或无感音频能力；视频 DOM 过滤和弹幕过滤应独立降级，不得静默把 BGM 功能显示为可用。

### 7.2 首屏内嵌数据

当前页面首屏存在两类可利用数据：

- `createQuickPlayer({ awemeInfo: ... })` 中的当前视频对象；
- React/RSC 的 `recommendAwemeList` 序列化数据。

解析原则：

- 只读取内联 script 文本；
- 禁止 `eval`、`Function` 或执行网页字符串；
- 使用明确前缀定位、JSON 字符串解码和带字符串状态的括号平衡扫描；
- 解析失败只影响 BGM 识别，不能影响页面播放；
- 使用匿名化真实片段建立 fixture；
- 页面格式变化时 fail-open。

### 7.3 后续 Feed 响应

对页面原本发起的请求安装透明观察包装：

- 原始 `fetch` / XHR 必须以原来的 `this` 和参数调用，并把原 Promise / Response 交还页面；
- 元数据解析只在克隆响应上异步进行，不阻塞站点；
- 只观察同源、成功、已实测为 Feed/Aweme 的 JSON 响应；
- 端点 allowlist 必须来自实现阶段的真实网络证据，不在设计阶段猜测 URL；
- 对响应大小、解析深度、节点数和单次处理时间设上限；
- 任意读取、克隆、JSON 解析或字段提取错误都吞并到脚本自己的错误边界，绝不能改变原响应；
- 不修改请求、请求头、响应体、状态码或页面可观察的结果；克隆和异步解析仍可能增加 CPU、内存及微任务负担，因此“透明”只作为需测试的不改变语义目标，不作为零开销承诺；
- 不使用 `GM_xmlhttpRequest`，不声明 `@connect`。

若实测确认后续 Feed 只使用 `fetch`，首版不包装 XHR；只有发现第二种真实传输方式时才增加 XHR Adapter。

### 7.4 数据提取

字段提取支持经过 fixture 验证的 camelCase 和 snake_case 形态，例如：

- `awemeId` / `aweme_id`；
- `itemTitle` / `item_title`；
- `music.title`；
- `music.musicName` / `music.music_name`。

递归遍历必须有深度和节点数上限。只接受同时具有视频标识或足够唯一文本字段的对象，不把任意名为 `title` 的站点配置误认为 BGM。

## 8. 页面生命周期

控制器状态：

```text
stopped
  -> discovering
  -> observing
  -> gating
  -> navigating
  -> suspended
  -> stopped
```

- `discovering`：支持路由内等待 Feed 根；
- `observing`：已连接 Feed、活动卡片和弹幕观察；
- `gating`：当前或下一候选卡片处于有界视觉/音频门控；
- `navigating`：命中后已请求下一条，等待活动卡片改变；
- `suspended`：离开支持路由或触发跳过熔断；
- `stop()`：彻底断开资源并恢复脚本拥有的 DOM 状态。

使用 generation 标识当前 Feed 根，使用 epoch 标识一次卡片激活决策。所有异步入口在读取数据后、产生副作用前都必须再次校验 generation、epoch 和 `retired` 状态；断开 Observer 不能替代该校验，因为已经排队的回调仍可能执行。

生命周期要求：

1. 文档启动后立即安装必要的首屏数据和传输观察；
2. DOM 可用后发现 `[data-e2e="slideList"]`；
3. 根出现后连接根观察、活动卡片选择和当前弹幕观察；
4. 新增卡片只登记候选，同步提取 DOM 字段并生成当前配置 revision 的决策，不对整个 Feed 重扫；
5. 活动候选进入视口前执行预判；可见前台中仍未决时启动不可重置的目标 250ms 卡片 watchdog；
6. 活动卡片变化时，先将上一 epoch 标记 `retired`，再取消 BGM 等待和导航确认，并按 ownership token 恢复或保守放弃媒体状态；
7. Feed 根替换固定按以下顺序执行：递增 generation 并将旧根/旧 epoch 标记 `retired` → 取消导航、timer、frame 和 BGM 等待 → 断开旧 Observer → 撤销旧根门控并恢复可安全恢复的媒体/弹幕状态 → 连接新根；
8. 离开支持路由或文档变为 `hidden` 时，先递增 generation/epoch 使旧任务失效，再撤销视觉和弹幕 active class、恢复或保守放弃媒体状态，最后断开 DOM 观察；不得在后台标签页维持待判定空白或临时静音；
9. 文档重新 `visible` 或返回支持路由时创建新的 generation/epoch 并重新发现，不复用旧 DOM 引用、旧决策或剩余倒计时；
10. `stop()` 使用与根替换相同的“先失效、后取消、再恢复”顺序，随后卸载传输包装并清空内存缓存。

根发现使用“MutationObserver 主路径 + 低频健康检查 fallback”。fallback 只检查路由、根连接状态和当前根身份，不扫描所有卡片。

## 9. 当前活动卡片判定

不能只依赖“正在播放的 video”，因为抖音会保留多个预加载播放器。判定按以下信号组合：

1. 视口中心点命中的 `feed-item`；
2. 与视口中心距离最小且可见面积足够的标准视频卡片；
3. 卡片内播放中或最近开始播放的 `video` 作为加权信号；
4. 必须属于当前 Feed 根；
5. 直播、无视频元素或推广特殊卡片默认不进入首版处理。

IntersectionObserver 只负责提供候选变化信号，最终选择由纯函数基于快照计算。这样可以使用几何 fixture 测试虚拟列表和上下两张同时可见的情况。

## 10. 配置与菜单

建议存储键：

```text
douyinEnhancer.videoKeywordFilter.enabled
douyinEnhancer.videoKeywordFilter.keywords
douyinEnhancer.danmakuKeywordFilter.enabled
douyinEnhancer.danmakuKeywordFilter.keywords
douyinEnhancer.bgmKeywordFilter.enabled
douyinEnhancer.bgmKeywordFilter.keywords
```

每类两个菜单，共六个：

- `视频关键词屏蔽：未配置 / 已开启（N 个词） / 已关闭（已保存 N 个词）`
- `编辑视频屏蔽词（N 个）`
- `弹幕关键词屏蔽：...`
- `编辑弹幕屏蔽词（N 个）`
- `BGM 名称屏蔽：...`
- `编辑 BGM 屏蔽词（N 个）`

状态菜单行为：

- 未配置时点击直接打开编辑框；
- 已配置时点击切换开关；
- 编辑保存成功后立即更新控制器和菜单；
- 清空词表后回到“未配置”，运行态等同关闭；
- 持久化失败时保留旧运行态和旧菜单，不产生半更新。

菜单刷新复用稳定菜单 ID；如果当前 Tampermonkey 版本不支持可靠更新，则显式注销旧菜单再注册，测试确保不重复累积。

## 11. DOM 所有权与恢复

脚本允许写入的页面状态仅限：

- 视频卡片上的脚本专属决策属性；
- 弹幕节点上的脚本专属过滤属性；
- 必要的脚本专属 style 元素；
- 待判定媒体元素的临时 `muted` 状态及对应内存恢复记录；
- 可选的熔断/失败提示元素。

禁止：

- 删除、移动或重建抖音管理的 Feed、播放器和弹幕节点；
- 覆盖网站的 `style`、class、滚动高度或播放器设置；
- 通过网站音量按钮或持久设置实现临时音频门控；
- 把关键词、BGM 缓存或命中原因写入 DOM；
- 恢复不是脚本自己写入的隐藏状态。

提示 UI 若实现，应挂在 `document.documentElement` 下，使用独立前缀和 Shadow DOM 或严格作用域 CSS；默认自动消失，并支持 `prefers-reduced-motion`。

## 12. 故障策略

总体原则是 fail-open：增强功能失效时优先保持抖音原生可用。

| 故障 | 行为 |
| --- | --- |
| Feed 根或选择器变化 | 停止视频/BGM 过滤，弹幕若仍可定位则独立工作 |
| 当前卡片不确定 | 不跳过 |
| BGM 元数据缺失或关联不唯一 | 不跳过 |
| 可见前台 BGM 决策超过目标 250ms | 原子解除视觉/音频门控，对本激活周期标记 `bypass` |
| 可见前台弹幕正文超过目标 100ms 仍未就绪 | 对该弹幕标记 `bypass` 并显示 |
| 文档进入 `hidden` | 立即使当前 epoch 失效并 fail-open，取消门控计时；恢复可见后创建新 epoch |
| 视频门控或媒体状态恢复失败 | 立即撤销该卡片门控、停止自动跳过并限频提示 |
| 内嵌数据解析失败 | 记录一次限频错误，继续 DOM 功能 |
| Fetch 克隆或解析失败 | 原响应不受影响，停止处理该响应 |
| 下一条请求未确认 | 最多一次重试，随后放行并提示 |
| 连续跳过过多 | 触发熔断，暂停自动跳过 |
| Observer 构造失败 | 使用有界 fallback；仍失败则停用对应功能 |
| 配置存储失败 | 保持旧配置和旧运行态 |
| 控制器停止 | 恢复专属 DOM 状态并释放全部资源 |

错误日志默认不输出完整响应、视频 URL、账号标识或用户关键词。相同错误需要限频，避免控制台刷屏。

## 13. 性能预算

- 关键词只在配置变化时编译；
- 单次匹配复杂度为“字段文本长度 × 有效关键词数量”，首版不引入复杂索引；
- Feed MutationObserver 只收集新增/变化卡片；
- 弹幕 Observer 只处理新增、复用或文本变化的 `[data-danmu-id]`；
- 活动卡片重新判定按动画帧合并，每帧最多一次；
- 新卡片的 DOM 文本初判保持同步，避免已知命中内容进入下一次绘制；
- 可见前台中，视觉与音频门控的单卡目标期限为 250ms，不被 mutation、路由信号或重复元数据重置；实际回调可以因主线程繁忙而迟到，回调执行时必须先比较 `performance.now()` 截止时间再 fail-open；
- 弹幕决策同步完成；仅文本后填充在可见前台允许目标 100ms 等待；
- 后台标签页不承诺 250ms / 100ms 墙钟上限，也不维持门控；通过 Page Visibility 生命周期立即 fail-open；
- BGM 响应解析异步进行，单响应有大小、深度、节点数和处理时间上限；
- 元数据缓存最多 500 条；
- 低频根健康检查建议 500ms～1000ms，只执行 O(1) 身份检查；
- 控制器停止后不得保留轮询、Observer 或响应解析任务。

实现阶段需要用 15 分钟连续浏览检查：

- 内存缓存是否有界；
- Observer 是否随根替换泄漏；
- 控制台错误是否限频；
- 响应克隆是否造成明显卡顿；
- 高频弹幕下是否出现长任务；
- 门控样式是否造成 layout shift、闪黑或连续空白；
- 临时静音/暂停是否影响下一条允许视频的原始音量和播放状态。

## 14. 元数据与权限

预期 Userscript 头部只声明完成任务所需权限：

```text
@match https://www.douyin.com/*
@run-at document-start
@sandbox raw
@grant GM_getValue
@grant GM_setValue
@grant GM_registerMenuCommand
@grant GM_unregisterMenuCommand
@grant window.onurlchange
@noframes
```

不声明：

- `GM_xmlhttpRequest`；
- `@connect`；
- Cookie、下载、剪贴板或通知权限；
- 页面历史、标签页或账号数据权限。

Tampermonkey 官方说明：`@sandbox raw` 请求在页面 MAIN_WORLD 中运行；`window.onurlchange` 可用于 SPA URL 变化。实现和发布前应重新核对官方文档及目标 Tampermonkey 版本。

## 15. 测试方案

- 视频只匹配允许字段；
- BGM 只匹配名称字段。

- 匿名化 RSC `recommendAwemeList` fixture；
- 匿名化后续 Feed JSON fixture；

- `awemeId/gid` 精确关联；
- 无 ID、ID 冲突和同 ID 不一致元数据时拒绝关联；
- 描述、作者、数组顺序和当前缓存唯一性都不能建立关联；
- DTO 不包含认证字段、视频 URL或完整响应。

### 15.3 控制器测试

- 启动时根尚未出现；
- 根动态出现和根替换；
- 活动卡片切换；
- 新卡片在进入视口前完成视频文本预判；
- `pending -> allow/block/bypass` 状态只能按合法方向变化；
- `allow/block/bypass` 在当前 epoch 都是终局，迟到视频/BGM 元数据不能翻转；
- 配置 revision 不突袭重判当前稳定视频，只为未激活候选和下一次激活创建新 epoch；
- 视频关键词命中只发起一次下一条；
- 视频关键词命中不等待 BGM；
- 视频命中后在导航确认前保持视觉和音频门控；
- BGM 元数据稍后到达后命中；
- BGM 250ms watchdog 不可被重复事件延长，超时后对当前激活周期放行；
- BGM `bypass` 后的迟到元数据不突袭跳过当前视频；
- 下一条未确认时最多重试一次；
- 根替换先递增 generation 和 retire 旧 epoch；Observer、watchdog、解析和导航的迟到回调不能操作新根；
- 连续跳过熔断和解除；
- 连续预判命中不会揭示中间卡片；
- 临时静音通过 ownership token 和 `volumechange` 争用检测决定是否恢复，不使用值相等推断所有权；
- 媒体争用、元素复用和保守不恢复路径不会污染下一条允许视频；
- 文档进入后台时立即 fail-open 并取消门控，恢复前台时创建新 epoch；
- 前台 watchdog 回调迟到时按绝对截止时间 fail-open，后台不承诺 250ms / 100ms；
- 门控异常按固定顺序 fail-open，不残留静音或不可见状态；
- 弹幕首批、动态新增、文本后填充和节点复用；
- 弹幕默认隐藏未决节点，100ms 后无法提取正文则 `bypass`；
- 关闭/清空词表恢复脚本拥有的弹幕；
- 三类配置独立更新；
- `stop()` 释放 Observer、timer、帧、响应包装和 DOM 状态。

### 15.4 传输透明性测试

- 包装后 `fetch` 的参数、`this`、返回 Promise 和 Response 语义保持不变；
- 解析 clone 不消费页面原响应；
- 解析异常不改变请求结果；
- 非同源、非 allowlist、非 JSON 响应不克隆；
- 卸载后恢复原始函数，且只恢复脚本自己的包装；
- 若发现函数已被其他脚本再次包装，不覆盖后来者。
- 实测页面预先缓存原始 `fetch` 时，脚本能检测并停用后续响应观察，不错误声明已覆盖；
- 记录克隆解析对微任务、CPU 和内存的增量，不把“透明”解释为零开销。

### 15.5 菜单测试

- 未配置、开启、关闭三种状态；
- 有效词数来自规范化结果；
- 菜单不显示原始关键词；
- 保存失败不产生半更新；
- 刷新菜单不重复注册；
- 六个存储键互不串用。

## 16. 真实浏览器验收

浏览器验收必须在 Tampermonkey 中保存当前最新版脚本后执行，并区分源码测试与实页证据。

### 16.1 视频关键词

1. 使用当前视频描述中的临时唯一词；
2. 刷新首屏后命中并只切换一条；
3. 下滑后新加载视频继续生效；
4. 未命中视频可正常播放；
5. 关闭、清空和重新开启后立即符合菜单状态；
6. 连续命中触发熔断，不无限翻页；
7. 直播、广告或不支持卡片不被误处理。
8. 使用录屏逐帧检查：提前命中的视频不出现可识别画面，激活时命中的视频不进入稳定画面；
9. 使用系统或浏览器音频监测确认命中视频没有可听音频；
10. 允许视频的音量、静音和播放状态不被上一条门控污染。

### 16.2 弹幕关键词

1. 使用当前弹幕中临时唯一词；
2. 已显示和后续新增弹幕均被隐藏；
3. 其他弹幕保持原动画和交互；
4. 节点复用后新文本重新判断；
5. 关闭或清空后只恢复脚本隐藏的弹幕；
6. 高频弹幕下无明显卡顿；
7. 使用录屏逐帧检查命中弹幕不会先显示再隐藏；
8. 构造文本后填充节点，确认最长 100ms 后 fail-open，且不会永久隐藏。

### 16.3 BGM 名称

1. 从当前视频对象确认真实 `awemeId` 和 `music.title/musicName`；
2. 使用唯一名称词后当前或后续视频正确跳过；
3. 首屏内嵌数据和无限滚动响应各覆盖一次；
4. 卡片无 `awemeId/gid` 时必须 fail-open，即使描述 + 作者在当前缓存中唯一；
5. 制造重复描述、ID 冲突和同 ID 不一致元数据，确认均不会误跳过；
6. 禁止把相邻视频 BGM 错配到当前视频；
7. Network 面板确认脚本没有新增请求；
8. 对缓存命中场景确认视频在进入视口前完成判定；
9. 对可见前台的元数据延迟场景测量目标门控不超过 250ms，期间没有视频音频泄漏；
10. 对元数据超过期限场景确认视频正常放行，迟到元数据不会在观看中途突然跳过。

### 16.4 生命周期与兼容性

1. 硬刷新、SPA 往返和浏览器后退；
2. Feed 根替换和预加载卡片回收；
3. Edge + Tampermonkey；
4. Chrome + Tampermonkey；
5. 连续浏览 15 分钟；
6. 页面原生连播、音量、暂停和弹幕开关不被持久修改；
7. 连续配置 3～5 个可命中视频，确认中间卡片不闪现并落在第一条允许内容；
8. 让 Feed 根在 `pending` 和 `navigating` 期间分别替换，确认不会残留空白、静音或旧任务误操作新根；
9. 在 BGM `pending`、弹幕 `pending` 和导航期间切到后台，确认立即 fail-open；返回前台后使用新 epoch，旧 timer 不生效；
10. 门控期间手动或由网站改变静音状态，确认争用检测不会覆盖后来选择，也不会污染下一条允许视频。

## 18. 风险排序

| 风险 | 等级 | 应对 |
| --- | ---: | --- |
| BGM 元数据与当前卡片错配 | 高 | 仅允许 `awemeId/gid` 精确关联；无 ID、冲突或不一致均放行 |
| 自动下一条重复触发或跳两条 | 高 | 单控制器、确认前互斥、一次 fallback、先递增 generation/retire epoch，再清理旧任务 |
| 临时静音覆盖用户/网站选择 | 高 | ownership token、`volumechange` 争用检测、争用时保守放弃恢复并验证下一卡状态 |
| 注入晚于 fetch/首帧/首音频 | 高 | Stage 0 时序硬门槛；不满足时分别降级 BGM 观察和音频无感承诺 |
| 页面响应格式变化 | 中高 | fixture、allowlist、安全解析、失败仅降级 BGM |
| 混淆 class 变化 | 中 | 优先 `data-e2e` / `data-danmu-id`，易变细节集中在内部页面函数 |
| 规则过宽导致翻页风暴 | 中 | 连续跳过熔断、允许视频停留后重置 |
| 响应克隆造成性能损耗 | 中 | 同源端点 allowlist、异步解析、大小/时间/缓存上限 |
| 弹幕节点复用导致误隐藏 | 中 | 观察文本变化、每次复用重判、专属所有权恢复 |
| Tampermonkey sandbox 差异 | 中 | 首版限定 Chromium + Tampermonkey，并在 Stage 0 验证 |
| 后台 timer 节流延长门控 | 中 | `visibilitychange` 时立即 fail-open；目标时限仅适用于可见前台 |

## 19. 最终建议

可以做成油猴脚本，且视频关键词和弹幕关键词适合直接采用 DOM 增强实现。BGM 名称过滤也可行，但它不是纯 DOM 功能，应被设计为可独立降级的数据增强层：只有在取得并可靠关联页面已接收的元数据时才跳过，否则放行。

首版不应追求“一次覆盖抖音所有页面”。先把推荐流、下一条互斥确认、弹幕节点复用和 BGM 关联做成可测试的深模块，能显著降低抖音前端变化时的维护范围。

## 20. 对抗式审查意见处置

2026-08-13 的独立审查结论为“可进入纯证据采集 Stage 0，但需先修订才能进入功能编码”。本方案按以下方式处置：

| 审查意见 | 处置 | 方案变化 |
| --- | --- | --- |
| 描述 + 作者的缓存唯一性不能证明视频身份 | 采纳 | 首版 BGM 只允许 `awemeId/gid` 精确关联，无 ID 一律放行 |
| 用属性值相等判断媒体所有权不成立 | 调整采纳 | 改为 ownership token + `volumechange` 争用检测 + 条件恢复；争用时不猜测所有权，并把“不污染下一卡”设为 Stage 0 硬门槛 |
| 根替换时先恢复、后递增 generation 存在迟到任务竞态 | 采纳 | 固定为先递增 generation/retire epoch，再取消、断开和恢复；每个异步副作用前复核身份 |
| `allow` 终局、迟到元数据和配置立即生效语义冲突 | 采纳 | 补完整状态转换；`allow/block/bypass` 对当前 epoch 终局；视频/BGM 配置不突袭跳过当前稳定视频 |
| `document-start + raw` 不能直接推出早于 fetch/首帧/首音频 | 采纳 | 改为 Stage 0 时序硬门槛；失败时分别降级 BGM 响应观察和音频无感承诺 |
| 后台标签页 timer 会被节流 | 采纳 | 250ms/100ms 仅定义为可见前台目标；进入后台立即 fail-open，返回后新建 epoch |
| `pause()` 后 `play()` 可能受自动播放策略限制 | 采纳 | 首版默认只使用临时 `muted`；`pause()/play()` 不作为实现或补救路径 |

没有采纳“只要争用就永不恢复任何媒体状态”的字面实现，因为它可能把脚本静音残留到站点复用的下一张卡片。替代方案是把争用检测、条件恢复和下一卡不受污染共同列为 Stage 0 门槛；若无法同时满足，则不采用直接修改媒体元素的音频门控方案，并降低“零可听音频”承诺。
