# Stage 3 弹幕关键词证据报告

> 日期：2026-08-13
> 当前候选版本：`douyin-web-enhancer.user.js` `0.3.0`
> 状态：源码实现和 Node 回归完成，待 Chrome + Tampermonkey 正式脚本实页验收

## 1. 实现范围

本阶段处理抖音 Web 各类视频页面中的可识别弹幕，与推荐流和自动下一条无关：

- 以 `document.documentElement` 作为页面级观察和所有权根，只分类 `[data-danmu-id]`；
- 以 `[data-danmu-id]` 作为唯一所有权单元；
- 只匹配节点显示文本，不读取作者、用户 ID、点赞数或菜单文字；
- 命中后添加 `data-dwe-danmaku-state="block"` 并由专属 CSS 隐藏；
- 不删除、移动或重建抖音节点，不修改抖音弹幕开关；
- BGM、媒体静音和响应观察仍未启用。

弹幕规则生效时，当前弹幕根使用 `data-dwe-danmaku-active` 进入首绘门控。无正文节点先标记 `pending`；正文在 100ms 内后填充则立即重判，超时仍为空则 `bypass` 并显示。该 100ms 是前台源码目标，尚未由高帧率实页录屏证明。

## 2. 生命周期与恢复

实现覆盖：

- 首批弹幕同步分类；
- 动态新增节点；
- `characterData` 文本后填充；
- `data-danmu-id` 变化和节点复用；
- 被移出 DOM 的节点立即撤属性并取消 watchdog；
- 弹幕根替换和活动视频切换；
- 配置更新立即重判当前弹幕；
- 关闭、清空、后台切换和 `stop()` 只恢复脚本拥有的属性；
- 单视频弹幕结构或正文 Adapter 异常时，先撤根门控并只降级弹幕模块，不停止视频过滤；下一活动视频重新尝试。

视频和弹幕共享推荐页/Feed 根生命周期，但各自持有独立的 Observer、记录和清理路径。仅启用弹幕时不会创建视频 epoch；关闭视频而保留弹幕时会撤销全部视频属性和 timer。

## 3. 源码验证

Stage 3 专用回归覆盖 13 个场景：

- 初始节点只处理当前活动卡；
- 新增和文本后填充；
- 空正文 100ms fail-open；
- 节点复用不继承旧决策；
- 移出 DOM 立即清理；
- 配置即时生效和关闭恢复；
- 活动卡/弹幕根替换；
- 后台立即恢复；
- 初始扫描与配置重判异常独立 fail-open；
- 视频/弹幕共享生命周期的启停组合；
- 弹幕异常只暂停当前活动视频，下一视频重新尝试。

首次实页验收发现，当前抖音把可见 `[data-danmu-id]` 节点放在活动卡内、但不放在 `[data-e2e="danmaku-container"]` 后代中：连续 12 次采样均为语义容器 0 条、全局 3–4 条，可见目标词同时存在。旧实现因此成功读取配置并挂载语义容器，却观察不到真实弹幕节点。

实页进一步确认独立 `/video/{id}` 页面没有推荐活动卡，但存在真实 `[data-danmu-id]`，稳定播放器祖先为 `[data-e2e="video-detail"]` 内的 `[data-e2e="player-container"]`。因此弹幕模块改为页面级观察，不再依赖任何推荐流或播放器容器选择器；Observer 回调仍只处理受影响节点，单节点解析异常只放行该节点。

保存该版后的双页面实测中，独立视频页含目标词“你”的弹幕被标记为 `block` 且计算样式不可见，实页通过。推荐页模块已挂载，但切换视频后的动态弹幕节点没有状态；根因是弹幕 Observer 错误复用了视频 Feed `generation`，Feed 初始化后把仍有效的弹幕 Observer 判为旧代。修复为独立 `danmakuGeneration` 后，推荐页初始动态弹幕均得到 `allow` 状态，但连续切换时仍观察到属于当前活动卡、在视口内且有正文的无状态节点，说明站点批量挂载存在 Observer 漏事件路径。

`0.3.1` 曾增加 750ms 漏事件健康补判。`0.4.9` 的发布前审查发现它仍会周期性查询整页未决弹幕，违反 O(1) 根健康检查约束，因此已移除：弹幕首批、动态新增、文本后填充和节点复用由增量 MutationObserver 处理，健康检查只核对路由与根身份。

正式保存并刷新后的 Chrome + Tampermonkey 复测通过：推荐页首个样本 7 条非命中弹幕全部 `allow` 且可见，0 条未判定；独立视频页 2 条非命中弹幕 `allow` 且可见，1 条含“你”的弹幕 `block` 且不可见，0 条误隐藏。推荐页再连续切换三条视频，前两条无弹幕样本，第三条 1 条非命中弹幕为 `allow` 且可见；全程无未判定节点和脚本错误。该证据确认功能正确性与漏事件恢复，但不能证明首绘零闪现或 100ms/750ms 的逐帧实际调度。

## 4. 待实页验收

在 Tampermonkey 保存 `0.3.0` 并刷新推荐页后，需要人工验证：

1. 从当前视频真实弹幕显示文本选取窄关键词，命中弹幕隐藏，其他弹幕仍显示；
2. 连续播放期间动态弹幕持续正确过滤；
3. 切换视频后旧弹幕不残留隐藏属性，新视频弹幕继续工作；
4. 修改关键词立即重判当前弹幕；
5. 关闭或清空弹幕规则后当前弹幕恢复，页面弹幕开关和发送功能不受影响；
6. 控制台没有脚本错误，视频自动跳过与原生播放状态不受弹幕模块影响。

高帧率首绘、文本后填充与节点复用在真实页面本轮仍未验证，不得写成通过。
